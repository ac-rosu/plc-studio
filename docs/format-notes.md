# Format notes

A log of every format fact or surprise found in exported files, one dated entry each, with its evidence (case, file, line). Parsers, writer and version profiles are built on these facts, never on guesses (CLAUDE.md rule 7). A fact is V21-only until a V20 case confirms it.

## 2026-10-23 – V21 corpus findings (summary)

The full answers, with exact evidence, are in [corpus/V21/_project/format-findings.md](../corpus/V21/_project/format-findings.md) (findings 1–9) and the build log in [run-log.md](../corpus/V21/_project/run-log.md). This entry is a short index. Where the two differ, the findings file wins.

- **Encoding and line endings** (finding 8): UTF-8 and CRLF in every file, with no bare LF anywhere. Files TIA writes (VCI SimaticSD, `.scl`/`.udt`/`.db`, SimaticML) start with a BOM. The export tool's text in `documents/` has no BOM but is otherwise byte-identical to VCI's files (finding 7). Endings: `.s7dcl`/`.s7res` end with one CRLF, external sources with CRLF CRLF, SimaticML with no newline after `</Document>`. The writer must keep each file's BOM state.
- **OB attributes** (finding 1, M0 open fact): not in `.s7dcl` or `.scl`. Details and the deferred decision are in [DECISIONS.md](../DECISIONS.md), 2026-10-23.
- **F-block detection** (finding 2, M0 open fact): the `.s7dcl` header attribute `S7_Safety`, spelled `"TRUE"` on F-FB/F-FC and `"True"` on F-DBs. The F instance DB also has `S7_UserDefinedId := "FUSI"`. An F-UDT has `{ S7_Safety := "True" }` before the type name. The language attribute is the standard `LAD`/`FBD`. There is no marker in `.s7res`, and none in the `.db` source of an F-DB. SimaticML uses `F_LAD`/`F_FBD`/`F_DB` and `IsFailsafeCompliant`.
- **`.s7res` layout** (finding 3, M0 open fact): a YAML subset. The first line is `MultiLingualTexts:`, then `  - id: <id>` followed by `    <culture>: <text>` lines. Cultures are in alphabetical order. A missing translation leaves out its line; a text with no language leaves out its id. Ids are free strings and unique only per file; TIA-made ids are `MLC_` plus 2–3 alphanumerics and stay stable across exports. Order is first reference in the `.s7dcl`: members, then networks, with each title before its comment. A value is single-quoted when it contains `: ` or ` #`. A block with no texts has no `.s7res`. Block title and block comment are in neither `.s7dcl` nor `.s7res`.
- **Line numbering** (finding 4, M0 open fact): TIA's SCL line n is the n-th line after `BEGIN` (`.scl`) or after `NETWORK` (`.s7dcl`); line 1 is the empty first body line. LAD/FBD messages give only "Network n" (the n-th `NETWORK`). An SCL network in a LAD block gives only the network. Declaration errors give "Interface", with no line. TIA reports where its parser notices the problem, which is not always the faulty statement (B03, B26).
- **IEC check** (finding 5): `.s7dcl` has `S7_IECCheck := "TRUE"` when it's on and no attribute when it's off. `.scl` does not store it, and regenerating from source resets it to off.
- **Software units** (finding 6): the `.s7dcl` is wrapped in `NAMESPACE <ns> … END_NAMESPACE`, indented 4 more spaces. `S7_UnitAccess` is always written. References are qualified from the root (`_.Filling.FB_Filler`) and unqualified inside the same namespace. An unresolved reference is one quoted identifier in `.s7dcl` (`"_.Dosing.FB_Doser"`) but stays unquoted in `.scl`. Unit name and relations appear in no file; only the namespace does.
- **Inconsistent blocks** (finding 9): `documents`, `source` and VCI SimaticSD exports work and carry no state marker. SimaticML export is refused.
- **LAD/FBD grammar as exported**: summarized in the run log, Step 2 (C16–C21). Includes the rewrites TIA applies between import and export (`MOVE(` → `Move(`, `Jump(` → `JumpCoil(`, Move's template line → an indented empty line).
- **V20**: not in v1 (DECISIONS 2026-10-24); no corpus. Every fact above is V21-only.

## 2026-10-24 – SIMATIC SD export drops AT overlays (surprise)

- Fact: in `FC_SclAtOverlay` (C09, non-optimized), the external source declares `RawBytes AT RawWord : Array[0..1] of Byte;` and SimaticML stores the overlay as `<StringAttribute Name="At" SystemDefined="true">RawWord</StringAttribute>`. The `.s7dcl`, both from the export tool and from VCI, declares only `RawBytes : Array[0..1] of Byte;`, with no `AT` and no attribute.
- Evidence: `C09-scl-advanced/source/FC_SclAtOverlay.scl` line 16; `C09-scl-advanced/simaticml/FC_SclAtOverlay.xml` lines 76–78; `C09-scl-advanced/documents/FC_SclAtOverlay.s7dcl` line 19 and `vci/SimaticSD/FC_SclAtOverlay.s7dcl` line 19. No `.s7dcl` file in the corpus contains `AT`.
- Consequence: a `.s7dcl` file cannot tell the extension that a variable overlays another. If such a file goes back into TIA, the overlay is probably lost and the variable becomes a separate one, which changes the program's behavior. To confirm on TIA (PLAN.md, owner actions): whether a `.s7dcl` import accepts `AT`, and what re-importing the exported file does to the block.

## 2026-10-24 – VCI SimaticML differs from the Openness export

- Fact: none of the 77 block and UDT SimaticML files VCI wrote is identical to the Openness export (`ExportOptions.WithDefaults`) of the same object. VCI leaves out the `<DocumentInfo>` header and attributes at their default value, for example `AutoNumber`, `HeaderVersion`, `Accessibility="Public"`, `Remanence="NonRetain"` and the system-defined `ExternalAccessible`/`ExternalVisible`/`ExternalWritable`/`SetPoint` attributes. UIds differ as a result. There are 4 short passages where VCI has lines the Openness export lacks; they were not analyzed further.
- Evidence: `C05-scl-sections/vci/SimaticML/FB_SclSections.xml` vs. `C05-scl-sections/simaticml/FB_SclSections.xml`; `B10-duplicate-case-label/vci/SimaticML/FB_SclSections_B10.xml` line 9 (`<Member Name="Enable" Datatype="Bool">`) vs. the Openness file (`Remanence="NonRetain" Accessibility="Public"` plus three `BooleanAttribute`s).
- Consequence for v1: the tag tables in the corpus (`tagtables/*.xml`) are VCI files, so only the VCI form of a tag table has samples. The tag-table reader must apply TIA's defaults for missing attributes, and a tag table exported through Openness (with defaults written) is needed as a corpus sample.

## 2026-10-24 – Verification batch in TIA V21 (corpus C27–C34, B27–B38)

Twenty small blocks were imported into the corpus project (group `Verify` of PLC_Main), compiled and exported with the TIA MCP server. The project was not saved. Results, each recorded as a corpus case:

- **SIMATIC SD has no AT overlays.** Importing `RawBytes AT RawWord : Array[0..1] of Byte;` in a `.s7dcl` fails: "Syntax error 'RawWord' expecting IQM address". In SIMATIC SD, `AT` takes an I/Q/M address only. So an overlay cannot be expressed in `.s7dcl` at all; a block with one cannot round-trip through SIMATIC SD (finding of 2026-10-24 confirmed). The parser accepts `AT %…` addresses.
- **New construct samples:** `FOR … BY -2`, `GOTO` with a label written `Label: statement`, and `RETURN` (C28, also as source); `N_Coil( operand => …, bit := … )` (C29).
- **Export normalizations:** an empty line before the first `{ S7_Language … }` network attribute block; an output passed with `:=` is exported as `=>` (C30); single-letter names that clash with address mnemonics are quoted (`"b"`, `"i"`, `"d"`, `"l"`, `"m"`, `"p"`, also `"by"`, `"t"`, `"w"`, `"a"`), while `x`, `y` and `r` are not.
- **Accepted by TIA:** an output passed with `:=` (C30); the integer literal `1` into a Bool (C31); a quoted local name with a space, `"Two words"` (C32); Int→Real, Int→DInt, Real→LReal with the IEC check on (C33); DInt→Time and Time→DInt without it (B35 lines 5–6); a Real literal into an Int, with a warning (C34).
- **Rejected by TIA:** FC call without an output (B27) or an input (B28); `=>` on an input (B29); unknown UDT member (B30); Int variable on TON's Time input PT (B31); assignment between two different UDTs (B32); GOTO to an undefined label (B33); Real→Int with the IEC check (B34); Word→Real even without it (B35); Bool→Byte (B36); a string literal into an Int (B37); Byte→Bool and Int→Bool (B38).
